# PCB 三维查看

## 设计与范围

在已有 PCB 工作区加入 2D / 3D 切换。三维显示实际板框、板厚、钻孔、顶底铜与丝印，以及工程绑定的官方器件模型；支持旋转、双指缩放和平移、滚轮、适应窗口、顶面/底面视角和器件显隐。仍为只读，不加入 CAD 编辑、STEP 导出或外壳 STL 查看。

沿用独立渲染器与 Rust 业务主体。Rust 负责解析、三角化、模型请求和装配矩阵，React Native 只处理显示和相机。比较过 Three.js + 原生适配、原生 wgpu 和共享 WebGL：本阶段选择 WebGL / Expo GL，使用简单光照、顶点色和按需绘制，避免再引入场景框架和两套原生渲染宿主。Expo GL 是新增原生依赖，必须重新构建移动包。

板面由已重放的几何生成，不使用官网缩略图。板框闭环和内孔参与三角化；独立圆弧端点允许 5 μm 的舍入误差，真实开口不自动跨接，缺少闭合板框时明确使用包围盒预览。钻孔先取并集再从板体扣除，避免重叠钻孔被填回；板面铜和丝印也受板体裁剪。板厚取顶底铜之间的 `LAYER_PHYS` 厚度之和；没有有效叠层时按 1.6 mm 预览并提示。原始 mil 转为 mm 只发生在 Rust 三维编译边界。

器件关联从 COMPONENT 属性、板级 ATTR 覆盖和 DEVICE 元数据解析，空覆盖表示显式取消绑定。官方模型属性使用 `3D Model`、`3D Model Transform`；变换遵循官方格式说明中的 sizeX/Y/Z、rotZ/X/Y、offX/Y/Z，再应用组件旋转、位置和底面变换。OBJ 的材质仅消费内嵌颜色，不自动请求材质/贴图中的外部 URL。

接口在同一 Rust 场景缓存中保存三维所需的小型装配元数据，避免再次下载完整工程。进入三维后才三角化和下载模型；网络请求只通过既有 HTTPS 白名单和大小限制。几何按位置/法线/颜色去重，用 base64 编码的 little-endian f32 和 u32 三角索引传输，上传 GPU 后不在手势里跨桥。客户端上传前将顶点布局压缩为 20 字节（位置保留 f32，法线和颜色使用归一化字节）；支持 ANGLE instancing 的设备把同一模型的多个器件合并为一次绘制，不支持时回退逐器件绘制。不支持 u32 索引的设备在上传时展开一次。重复器件共享模型缓冲，模型请求最多三个并发，GPU 缓冲上限 64 MiB；失败保留板体并允许重试，不把缺失器件伪装成完整装配。

切回二维保留原画布、相机和图层。三维相机输入合并到下一动画帧，静止时不持续刷新；离开查看器释放 GPU 资源、事件监听和待绘制帧。UI 沿用现有深色紧凑工作区，窄屏工具可换行，触控目标至少 44px。

2026-10-23 离线重放此前完整采集的 ESP32-S31 工程：282,807 条记录、266 个文档；三维板框为 64 × 36 mm，叠层厚度为 1.5861538 mm，239 个器件中 238 个有模型绑定，共 34 类模型。索引优化后的 Release 编译板体约 241 ms，原 1,012,656 个顶点去重为 368,214 个顶点与 1,012,656 个索引，GPU 缓冲从 36,455,616 降至 17,306,328 字节。这是本机缓存的真实工程验证，不是本轮在线下载结果；原始工程和解密记录不提交。

2026-10-24 本机 1440 × 900 浏览器回放同一真实板，模型请求明确注入离线失败：WebKit 首次切换约 1,019 ms，60 次方向键旋转的帧回调间隔中位数 12 ms、P95 13 ms；Chromium SwiftShader 软件 GPU 的同类采样中位数 115.5 ms、P95 130.9 ms。截图检查了实际板框、开槽、焊盘、铜和丝印。此测试测量输入与动画帧回调间隔，不能等同 GPU 呈现耗时或真机帧率；两种后端结果分别记录，不相互泛化。

前一轮验收中，`pro.lceda.cn` 对工程和模型元数据请求返回 418 或超时。2026-10-24 已成功在线加载泰山派 3M 的完整工程。模型链路按安装包中的 v5 components 端点、公开资源的 `3d_model_uuid` 字段及 modules 模型 URL 实现，OBJ 解析和装配矩阵已离线验证；v5 在线响应形状与实际器件下载仍未验收。模型失败时明确显示数量和重试入口，板体可继续操作。

## 2026-10-24 场景大小限制修复

旧实现把合并前的板面三角顶点、展开后的三角顶点和索引共用 150 万上限。它会拒绝最终网格仍能放入显存预算的板子：泰山派 3M 有 45,117 个二维对象，最终三维网格仅约 33.47 MiB，但需要 1,949,982 个索引，超过旧上限。

现在三角形生成时就按位置、法线、颜色建立索引，结束构建后释放去重表；不再保留整份展开顶点再复制去重。OBJ 的逐角法线在建立索引前确定，硬边不会因共享位置而被抹平。器件 CPU 缓存预算同时计算顶点与索引。

板面按原始轮廓点累计工作量，同材质每累计约 65,536 个临时三角顶点就合并一次，并统一外环方向，保留孔洞方向。重复和重叠图形因此不会不断堆积成一份巨大临时三角列表。保留独立的输入与输出保护：板面输入最多 200 万轮廓点，单图形最多 50 万轮廓点；最终网格最多 150 万独立顶点、600 万索引，顶点和索引的实际字节总和不超过 64 MiB。渲染器对板体和所有器件仍共用 64 MiB GPU 预算；旧 WebGL 设备需展开索引时，在分配展开数组前先核算占用。

`pcb.solid.limit` 记录触发阶段、实际数量和上限；`pcb.solid.complete` 记录最终独立顶点、索引、网格字节与编译耗时。GPU 预算不等同于进程峰值内存，也不保证任意数量三角形都能流畅交互。真实工程及回归结果见 [validation.md](validation.md)。

原生正式包、最终检查、审阅修复和未测范围见 [validation.md](validation.md)。当前仍未取得真机持续手势 FPS、功耗与峰值内存数据。
