# PCB 三维查看

## 设计与范围

在已有 PCB 工作区加入 2D / 3D 切换。三维显示实际板框、板厚、钻孔、顶底铜与丝印，以及工程绑定的官方器件模型；支持旋转、双指缩放和平移、滚轮、适应窗口、顶面/底面视角和器件显隐。仍为只读，不加入 CAD 编辑、STEP 导出或外壳 STL 查看。

沿用独立渲染器与 Rust 业务主体。Rust 负责解析、三角化、模型请求和装配矩阵，React Native 只处理显示和相机。比较过 Three.js + 原生适配、原生 wgpu 和共享 WebGL：本阶段选择 WebGL / Expo GL，使用简单光照、顶点色和按需绘制，避免再引入场景框架和两套原生渲染宿主。Expo GL 是新增原生依赖，必须重新构建移动包。

板面由已重放的几何生成，不使用官网缩略图。板框闭环和内孔参与三角化；独立圆弧端点允许 5 μm 的舍入误差，真实开口不自动跨接，缺少闭合板框时明确使用包围盒预览。钻孔先取并集再从板体扣除，避免重叠钻孔被填回；板面铜和丝印也受板体裁剪。板厚取顶底铜之间的 `LAYER_PHYS` 厚度之和；没有有效叠层时按 1.6 mm 预览并提示。原始 mil 转为 mm 只发生在 Rust 三维编译边界。

器件关联从 COMPONENT 属性、板级 ATTR 覆盖和 DEVICE 元数据解析，空覆盖表示显式取消绑定。官方模型属性使用 `3D Model`、`3D Model Transform`；变换遵循官方格式说明中的 sizeX/Y/Z、rotZ/X/Y、offX/Y/Z，再应用组件旋转、位置和底面变换。OBJ 的材质仅消费内嵌颜色，不自动请求材质/贴图中的外部 URL。

接口在同一 Rust 场景缓存中保存三维所需的小型装配元数据，避免再次下载完整工程。进入三维后才三角化和下载模型；网络请求只通过既有 HTTPS 白名单和大小限制。几何用 base64 编码的 little-endian f32 传输，上传 GPU 后不在手势里跨桥。重复器件共享模型缓冲，模型请求有并发限制，失败保留板体并允许重试；不把缺失器件伪装成完整装配。

切回二维保留原画布、相机和图层。三维相机输入合并到下一动画帧，静止时不持续刷新；离开查看器释放 GPU 资源、事件监听和待绘制帧。UI 沿用现有深色紧凑工作区，窄屏工具可换行，触控目标至少 44px。

## 来源与边界

- [官方元件与 3D 变换说明](https://github.com/easyeda/easyeda-file-format/blob/main/en/pcb/component.md)。
- [官方 STEP / OBJ 导出说明](https://prodocs.lceda.cn/cn/pcb/export-3d-file/)。
- 只复用公开工程关联的模型资源，不复用 easyeda-viewer 或闭源 smt-gl-engine 实现。
- 模型覆盖率、板厚、特殊叠层与原生设备性能必须分别验收，不把桌面离线夹具结果泛化为全部工程。

2026-10-23 离线重放此前完整采集的 ESP32-S31 工程：282,807 条记录、266 个文档；三维板框为 64 × 36 mm，叠层厚度为 1.5861538 mm，239 个器件中 238 个有模型绑定，共 34 类模型。Release 编译板体约 222 ms，输出 1,012,656 个交错顶点。这是本机缓存的真实工程验证，不是本轮在线下载结果；原始工程和解密记录不提交。

当前 `pro.lceda.cn` 对工程和模型元数据请求返回 418 或超时。模型链路按安装包中的 v5 components 端点、公开资源的 `3d_model_uuid` 字段及 modules 模型 URL 实现，OBJ 解析和装配矩阵已离线验证；v5 在线响应形状与实际器件下载仍未验收。模型失败时明确显示数量和重试入口，板体可继续操作。
