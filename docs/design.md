# OSHWHub 跨端客户端设计

日期：2026-10-23（Asia/Shanghai）。首轮范围已由用户确认：先完成公开浏览和 PCB 查看，再迭代账号功能。

## 目标与边界

在 Android、iPhone/iPad 和 Windows/macOS/Linux 桌面端复用 React Native 界面。支持公开工程信息流、分页、搜索、排序、工程详情、BOM、板子选择和二维 PCB 查看。能在 320px 手机、小屏横屏、平板分屏和宽屏窗口中伸缩，保留安全区域、可访问标签和键盘操作。平台支持、实际构建、模拟器验证和真机验证分别记录，不用“完美适配”代替验收。

参考 `/Users/gouzi/Downloads/app_zh_release.apk`（Bambu Handy 4.3.0）的搜索、分类标签、卡片信息流和底部导航布局；不复制其代码和素材。桌面端使用侧栏和可伸缩内容区；详情和查看器在窄屏以独立页面呈现，在宽屏利用额外空间。

本轮不实现账号登录、评论写入、云收藏同步、PCB 编辑、三维模型或制造导出。离线数据必须明确标注，不能用示例冒充实时工程。

## 技术选择

- React Native + Expo，使用开发构建接入本地 Rust 模块；不以 Expo Go 作为原生桥验收。
- React Native Web + Tauri 2 作为桌面外壳，保持页面和交互代码共享。桌面 HTML 是同一套 React Native 组件编译结果。
- Rust 2024 workspace：共享核心执行网络访问、参数校验、分页和字段归一化、正文安全转换、BOM 解析、EDA 历史下载/解密/合并与压缩归档。
- Android 通过 Expo Modules + JNI 调用 Rust；iOS 通过 Expo Modules + C ABI；桌面通过 Tauri command。协议为版本化 JSON，请求/响应有稳定的类型与结构化错误。
- 浏览器仅作开发预览，通过只绑定 loopback 的 Rust 开发服务调用相同核心；正式移动和桌面包不依赖该服务。
- PCB 使用自研二维渲染器：Rust 重放文档状态、转换几何、生成图层绘制批次和执行拾取，React Native Skia 绘制本地场景。移动端使用原生 Skia，桌面使用同组件的 CanvasKit 后端；不复用 `easyeda-viewer` 或闭源 `smt-gl-engine` 的实现。

对比方案：全部 JS 业务实现不满足 Rust 业务主体要求；已有二维预览器虽能减少首轮工作，但用户已明确要求自研。采用独立文档、场景和绘制三层，格式兼容与 GPU 绘制分别验证。此处的“smt-gl-engine”表示自研图形引擎方向，不表示已复刻专业版全部功能。

UI -> bridge -> Rust core；渲染器只消费 Rust 准备的场景，不直接访问官网接口。核心测试不依赖手机、桌面 WebView 或外网。网络测试独立运行并明确标记。

## 玻璃导航

窄屏使用悬浮胶囊式底部导航，宿主宽度最多 480px；宽度达到 1024px 时切换为总宽 216px 的圆角玻璃侧栏。保留绿色强调色、统一线条图标、文字和可访问的 tab 选中状态，触控目标至少 44px。底部导航避开系统安全区域，内容可以从材质下方滚过；信息流、详情的加载/错误/正文以及静态页按导航实际测量高度添加末尾留白，文字缩放后重新测量。移动端 PCB 查看器收起导航，使用完整安全区域。

iOS 底栏通过已有 Expo 原生模块中的 `LiquidTabBar` 挂载真正的 `UITabBar`。标签、SF Symbol 名称和选中项来自 React Native；Swift 只设置控件并转发选择事件，不持有页面或业务状态。玻璃镜片、按压/拖动反馈、图标与文字排布、无障碍材质由 UIKit 管理，取消手绘绿色底块和额外玻璃外框。iOS 26+ 使用系统 Liquid Glass，旧系统自动使用当时的原生外观。此处选择系统控件，是因为单层 `GlassView` 无法自动提供系统 Tab Bar 的选中镜片和触摸行为；没有为此替换应用路由。平台行为依据见 [Apple UIKit 新设计](https://developer.apple.com/videos/play/wwdc2025/284/)。

iPad 宽屏侧栏仍使用与 Expo SDK 58 匹配的 `expo-glass-effect` 58.0.4，检查 Liquid Glass 与原生 API 可用性后启用 `GlassView` 的 clear 材质。旧系统、缺少原生 API 或用户开启“降低透明度”时使用不透明浅色面板。首次读取无障碍设置前也使用实色，订阅设置变化并在卸载时清理监听。iPad 竖屏改为系统底栏，横屏恢复侧栏并保留当前页面。原生控件新增或更新后需重新安装 pods 并构建开发客户端或 Release 包；只更新 Metro 不能添加原生视图。API 依据见 [Expo GlassEffect](https://docs.expo.dev/versions/latest/sdk/glass-effect/)。

桌面 WebView 和开发浏览器用 CSS `backdrop-filter` 模糊、饱和度、渐变透光、细亮边与阴影实现对应风格。侧栏背景增加轻微青/蓝色调，使透明面板有层次；去掉原先 74% 不透明白底。共享选中层按实际导航项边界移动：Web 直接提交目标位置，由 CSS 负责过渡，避免 JS 动画帧暂停后选中层留在旧位置；Android 和 iPad 侧栏使用原生驱动弹簧，只更新 transform。开启“减少动态效果”时立即定位，原生与骨架共用设置监听逻辑。图标由少量静态 View 线条组成，不加载字体或另启 Skia 画布。浏览器不支持滤镜或匹配 `prefers-reduced-transparency: reduce` 时面板和选中层都使用实色。Android 材质见下文。

桌面 CSS 效果仍是近似，不能提供 UIKit 的光学折射或系统触摸形变。桌面与 iOS 未增加逐帧截图或嵌套模糊；每种布局仅一块背景材质，PCB 的场景和绘制缓存不参与导航计算。真机帧率、功耗及各 WebView 的材质差异仍需分别采样。


### Android 玻璃材质选型

使用固定版本 [`expo-android-glass-view` 1.0.2](https://github.com/kagantemizkan/expo-android-glass-view)，Apache-2.0，复用 Kyant 的玻璃着色器。通过 `GlassSurface.android.tsx` 仅替换底栏/侧栏背景；保留 RN 的 tab、文字、触控和原生驱动选中层，不接管页面路由。Android 13+ 使用 AGSL 折射，Android 12 使用模糊，更老系统使用实色；启用系统减少动态效果时也回退实色，并立即定位选中层。首次读取该设置前先用实色。移动端进入 PCB 后底栏卸载，释放背景材质。

接入前核对 npm 发布源码：`ViewBackdrop` 把窗口背景记录到 RenderNode，只缓存导航边界和 32dp 余量；移动、滚动或玻璃挂载变化时重录，静止时复用，其他背景子树由 RenderNode 引用更新。`ViewBackdropCapture` 排除玻璃子树，避免把自身采进背景造成循环。没有后台定时截屏、整屏 Bitmap 软件绘制或 CPU 像素回读；退出时移除监听并释放缓存。不引入额外 JNI ABI，Compose 运行时由 Gradle 统一解析。该实现仍有 GPU 模糊/折射开销，且库尚年轻，不能从源码推断所有设备都流畅。

## 数据与错误处理

公开 API 使用固定站点，允许列表、搜索、详情和工程元数据查询。UUID、页码、关键词长度在 Rust 边界校验。网络请求设置连接/总超时、响应大小和重定向限制；不能把服务器返回的任意 URL 当作可下载目标。详情 HTML 转成安全的内容块，外链仅允许 http/https，不在应用内执行工程正文中的脚本。

错误协议包含 code、用户可理解的 message 和 requestId。界面区分加载、无结果、服务拒绝、离线和损坏工程，提供重试。切换搜索/详情后过期响应不得覆盖当前结果。页码只在成功后推进，重试不得重复卡片。

账号与凭据不进入首轮。日志只记录请求类型、状态、耗时、数量和关联 ID，不记录正文、Cookie、Authorization、解密密钥和完整个人信息。原生核心使用 `tracing`，界面记录渲染/桥接故障；调试日志与运行说明一起提供。

## 物料清单

BOM 保留官网的字段对应关系，使用中文标签：序号、名称 / 参数、位号、封装、数量、制造商型号、制造商、供应商、供应商料号。Rust 分别归一化这些业务字段，界面不再用分隔符把不同字段拼成一个无标签的字符串；序号按原始 BOM 顺序生成，筛选后保留，不作为器件 ID。

物料表上方提供即时搜索，覆盖八个原始字段；关键词去除首尾空白、忽略大小写，按普通文本子串匹配，空白关键词恢复全部。Rust 的本地 `searchBom` 命令返回原始行索引，保持顺序与源数据，不重新请求官网。输入防抖 180ms，回车立即查询，筛选时有进度动画，显示匹配种数 / 总种数；无匹配时提示更换关键词或清除，桥接错误另行显示并可重试。过期响应不会覆盖新结果。清除按钮恢复全表，切换板子清空关键词，窗口尺寸变化保留关键词。

详情可用宽度达到 720px 时用带表头、对齐列和交替行底色的表格，表宽 1040px；宽桌面可同时查看全部字段，较窄窗口只在表格内部横向滚动，并支持键盘聚焦后滚动。更窄时每条物料显示为标签和值逐行对应的卡片。两种布局共用字段定义，保持名称、位号、型号与料号的区别；空白字段统一显示“未提供”，数量 0 保留，长位号和型号自动换行，文本可选择复制。切换布局不改变所选板子。

此方案保留官网逐列对照的阅读方式，同时让手机无需来回横向滚动才能理解单项物料。只在旧卡片上补几处文字仍不便于桌面横向比较；所有尺寸强制宽表则会增加手机查阅成本。没有增加表格依赖、物料图片、采购或排序功能。BOM 仍在详情头部一次挂载，不宣称已经对上千种物料完成虚拟化或性能验证。

## 加载与正文图片

首页、详情和远程图片使用共享脉冲骨架屏，追加列表和 PCB 解析保留进度动画。系统开启“减少动态效果”时骨架保持静态；原生动画不占用交互任务，避免阻挡 FlatList 的后续批次。

Rust 一次返回归一化正文，界面用 FlatList 首批/每批渲染 4 个内容块，窗口为 3 屏。只有可视项及下一项启用图片请求，远处图片保留静态占位；这属于分块渲染与按需下载，不是官网正文接口分页。BOM 展示方式见上文。

封面和正文图按实际布局宽度乘屏幕像素密度选择 320/640/960/1280/1920px 档位。只为没有查询参数的 `image.lceda.cn` 图片添加已验证的 CDN 缩放、80 质量及 WebP 处理；其他域名、签名链接和作者已有处理参数保持原样。正文图最大宽 960，解码后按自然比例计算高度，不设统一高度上限，避免整张长海报缩成窄条；同时提供原图链接。缩略请求失败回退原 URL，原图失败可独立重试，不必重新下载工程。布局重排导致的新请求忽略旧请求回调。图片错误日志仅含域名和是否为缩略请求。

官网用一张长海报承载整个介绍时，它仍是一个图片请求；分段渲染以接口的内容块为单位，没有把单张图片切成多个下载分片。

2026-10-23 同一正文 PNG 的一次网络对照：原 URL 响应 270,382 字节、2.38 秒；960px 缩略响应 53,258 字节、1.45 秒，体积减少约 80.3%。原响应本身也由 CDN 转为 WebP。该样本不能代表所有图片、整页时延或真机帧率；CDN 行为变化仍由回退路径兜底。

## PCB 文档与性能

`proImages` 只提供板子、PCB ID、缩略图和 BOM，不能替代真实 PCB。完整链路为项目元数据 -> 默认分支 -> 历史页 -> 下载载荷 -> AES-GCM 验证解密 -> gzip 解压 -> 按历史顺序和文档/记录 ID 合并 -> Rust 场景批次 -> Skia 本地绘制。

重放期间保留文档边界、图元 ID、ticket 和删除标记。只读场景编译后释放完整工程记录，缓存仅保留拾取需要的几何及标识，避免让历史删除记录长期占用手机内存。未来编辑入口应重新加载并持有完整工程状态，不能从有损绘制场景反推源文档。封装/字体/图片等依赖必须明确处理；历史链不完整、解密失败、未知结构或缺少必要依赖时报告错误/警告，不能静默展示一张“完整”板。格式支持按真实夹具和实际渲染结果记录。

查看器独立于 React 业务组件树，不能每条走线创建 React 节点。按图层/画笔批量构建和缓存 SkPicture；工程只在加载时跨桥，平移/缩放/图层切换留在绘制层，不在手势期间传整板 JSON。固定输入/解压大小和历史数量上限，拒绝压缩炸弹。记录下载、解码、合并、场景构建与首次绘制耗时，给出实际板子和设备信息，避免空泛性能承诺。

触控支持单指平移、双指中心缩放、缩放按钮、适应窗口；桌面支持鼠标滚轮、拖动、键盘和可访问工具栏。查看器卸载时释放事件监听、缓存和画布资源。

### PCB 工作区：参考 Shapr3D

参考 [Shapr3D 官方工作区说明](https://support.shapr3d.com/hc/en-us/articles/7873880676508-Shapr3D-modeling-space) 中的 macOS、iPadOS 实图及 [Items Manager](https://support.shapr3d.com/hc/en-us/articles/7873936188956-Items-Manager) 的按需侧栏。采用画布为主、工具沿边、选中后显示属性的布局；保留 PCB 二维只读范围。没有增加建模、历史编辑、3D 视图或无实际功能的工具。

进入查看器后收起应用导航，用紧凑深色标题栏显示返回、板名和只读状态。画布填满其余安全区域，左上角放图层、适应窗口和信息工具，右下角放缩放，左下角保留图元/图层数量。工具使用明确文字和至少 44px 触控区域；高度低于 500px 时改为横向工具组，避免短横屏裁切。查看器采用低反差深色面板和蓝色选中状态，不修改浏览页的玻璃导航。

图层由横排标签改为纵向可滚动列表，名称、图层颜色和显示状态分开呈现；切换后顺序保持不变。图层、查看器信息、选中属性共用同一面板位置，一次展开一个。手机竖屏从底部展开，平板/桌面及短横屏从右侧展开；开关面板不改变画布尺寸，不重新适应窗口，保留当前缩放、平移和图层选择。提示及性能耗时放入信息面板，有显示提示时在信息入口标出数量。拾取错误仍立即显示。

实现范围为共享 `ViewerPage`、`PcbViewer` 和应用导航的查看器显示条件，以及相关 E2E 和文档。复用既有场景、SkPicture 缓存和 Rust 拾取协议，不新增依赖，不在手势或面板开关中重编译场景。验证覆盖六种视口、面板互斥、图层状态保留、画布占用、缩放/平移/拾取及返回导航。

## 验收与持续集成

Rust 单测覆盖 API 归一化、URL/参数校验、错误、历史顺序、重复/删除/损坏记录、解密和解压上限。TypeScript 测试覆盖桥协议、异步过期响应、布局边界和查看器触摸计算。E2E 在手机、平板和桌面尺寸执行浏览、详情和 PCB 交互，检查溢出与运行时错误。

提交前运行 Rust fmt/clippy/test、TypeScript check、格式/静态检查和相关测试。使用 prek 固定本地检查入口。CI 安装锁定工具链和依赖，运行相同检查，并分别验证 Android、iOS 与桌面构建；上传构建产物和失败诊断。在线站点测试单独列出，不能以外部不可用掩盖离线单测失败。
